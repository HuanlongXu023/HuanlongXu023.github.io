功能详解

系统功能

RTC 时钟与闹钟 硬件时钟
  • 利用 STM32 内置 RTC 外设实现高精度时钟功能，掉电后通过纽扣电池保持走时
  • 用户可通过按键设置当前时间与闹钟时间，到达指定时间蜂鸣器自动响铃
  • 支持多组闹钟设置，EEPROM 掉电保存
联网获取实时天气 ESP8266 + HTTP
  • 通过 ESP8266 Wi-Fi 模块连接互联网，调用心知天气 REST API
  • 定时获取指定城市的实时天气数据（温度、天气状况、湿度等）
  • JSON 数据解析后更新至显示任务，OLED 实时显示天气信息
OLED 多信息显示 I²C
  • OLED 屏幕通过 I²C 总线驱动，同时显示时间、日期、天气信息
  • 多任务共享 I²C 总线，通过互斥量（Mutex）保证总线访问的互斥安全
  • 自定义字库与图标，界面清晰美观
技术难点与解决方案

攻坚过程

难点 1 — 任务优先级合理分配

OLED 显示任务对实时性要求高，设为较高优先级，避免显示内容卡顿；天气数据读取需要等待网络响应，属于低实时性任务，设为低优先级，让出 CPU 给更紧迫的任务使用。

难点 2 — 任务堆栈大小配置

天气数据读取任务需要缓存 HTTP 响应的 JSON 字符串，数据量较大。早期堆栈配置偏小导致系统随机卡死（栈溢出）。通过分析任务最大栈深度，为该任务分配足够的堆栈空间后，系统运行稳定。

难点 3 — 多任务共享 I²C 总线

显示任务与其他任务（如按键扫描后需要刷新显示）都需要访问 OLED 的 I²C 接口。若不加保护，两个任务同时写 I²C 会导致总线冲突、画面花屏。使用 FreeRTOS 互斥量（Mutex）保护 I²C 操作，同一时刻只允许一个任务访问，彻底解决冲突。

难点 4 — 显示任务与数据任务同步

天气数据异步更新，显示任务需要知道"数据已就绪"再刷新，否则会显示未初始化的脏数据。通过 FreeRTOS 队列消息或信号量实现两个任务间的生产者-消费者同步，显示任务收到通知后再读取最新数据绘制界面。
